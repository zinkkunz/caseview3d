# 클라이언트 사이드 업로드 구현 계획 (Presigned URL)

## 목표
Vercel 환경에서 발생하는 '서버 사이드 업로드'의 고질적인 문제(405/500 에러, 용량 제한, 타임아웃)를 해결하기 위해, AWS S3(R2) Presigned URL을 활용한 **클라이언트 직접 업로드** 방식으로 전환합니다.

## 아키텍처 변경 사항
- **기존 (현재)**: 클라이언트 -> POST /api/upload (파일 전송) -> 서버 (파일 처리/압축) -> R2 업로드
- **변경 (신규)**: 
    1. **URL 발급**: 클라이언트 -> POST /api/upload/presign -> 서버가 '업로드 가능한 URL' 반환
    2. **직접 업로드**: 클라이언트 -> PUT (Presigned URL) -> R2 저장소 (서버 부하 0)
    3. **DB 등록**: 클라이언트 -> POST /api/cases/create (파일 경로 및 메타데이터) -> 데이터베이스 저장

## 단계별 구현 상세

### 1. 백엔드: Presigned URL 발급 로직
- **`lib/storage.ts` 수정**: `getPresignedUploadUrl(key: string, contentType: string)` 함수 추가.
- **신규 API 생성 (`app/api/upload/presign/route.ts`)**: 
    - 요청: 파일명, 파일타입
    - 응답: `url` (업로드용 임시 링크), `key` (저장될 파일 경로)

### 2. 백엔드: 케이스 최종 생성 API
- **신규 API 생성 (`app/api/cases/create/route.ts`)**:
    - 기존 `upload/route.ts`의 로직에서 파일 처리 부분 제거.
    - 클라이언트가 보내준 `caseId`, `filePaths`, `memo` 정보를 받아 Prisma DB에 기록.

### 3. 프론트엔드: 직접 업로드 로직 구현 (`app/ClientPage.tsx`)
- **`handleSubmit` 함수 전면 수정**:
    - 파일별 병렬 처리 로직 구현:
        1. 서버에 Presigned URL 요청.
        2. 브라우저 `fetch(url, { method: 'PUT', body: file })`로 R2에 직접 전송.
    - 모든 파일 업로드 성공 시:
        - `/api/cases/create` 호출하여 케이스 생성 완료.
    - 진행률(Progress Bar) 표시 로직 보완.
